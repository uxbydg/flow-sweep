# Transcript Sweep

A concept for Wispr Flow's history view, built as a design-engineering artifact for the Wispr Flow
Design Engineer application. One screen, one action: find the transcript entries that are almost
certainly accidents, show them with the reason and a confidence, sweep them in one motion, and keep
them somewhere they can come back from. Built against one real user's 874 entries.

**Stack:** React 19, TypeScript, Vite, Motion, Lucide, SCSS modules. First React build, AI-paired.

## What the data said (from Flow's own local store, read-only)

874 entries, 8 Aug to 11 Sep 2026. **100 empty (11.4%), 83 under 20 characters (9.5%), 1 flagged
in the entry itself. 184 candidates, about 1 in 5. 145 preselected at 0.60.**

- **Empties are not brief hotkey taps.** They average 8.5 s of recording (max 152 s): recordings
  that returned no text. The taps are the under-20 set (2.6 s recorded, 1.6 s of speech). Two
  failures, two upstream causes; the store does not say why the text did not come back.
- **The retry pattern occurs once** in 874. Dropped.
- **Context decides what an accident is.** "Hi." into Messages is a text; "Hi." into Terminal is not.
  Confidence is weighted by the target app. This is the design in the project.
- **Storage is not the value.** All audio is 597 MB; the under-20 set carries 16 MB. The sweep buys a
  legible history, not disk.
- Prior art: Flow deletes one transcript at a time via a three-dot menu, offers auto-delete after
  24 h, and its docs say "deleted transcripts cannot be recovered." No bulk review, no undo. The
  Swept place is the answer to that sentence.
